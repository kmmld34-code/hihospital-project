## 1. 개요 및 수립 배경

본 문서는 2026년 9월 17일 심야 아키텍처 회의에서 **대표님께서 명확히 짚어주신 2WAY(Headless) 개발 방향과 게시판의 풀 페이지(Full Page) 서비스 원칙**을 체계적으로 정리하고, 향후 백엔드 프로비저닝부터 프론트엔드 라우팅 페이지 개발까지 팀원 전원이 한 치의 오차 없이 일관되게 추진하기 위해 김별 사원이 작성한 종합 아키텍처 지침서입니다.

### 📌 대표님 핵심 지침
1. **모달의 한계 극복**: 개인정보처리방침이나 이용약관 등 정적 문서는 모달이 편리할 수 있으나, **모든 동적 게시판(커뮤니티/치료후기 등)은 반드시 고유 URL을 갖는 독립된 전체 페이지(Full Page) 형태로 서비스**되어야 한다.
2. **2WAY 방식의 명확한 역할 분담**:
   - **백엔드(g7 Laravel)**: 게시판 DB 테이블 선행 생성 및 권한 설정, REST API를 통한 순수 데이터 제공.
   - **프론트엔드(Next.js App Router)**: 글 목록, 글 상세, 글쓰기 폼 페이지 자체를 완벽한 화면으로 구축하고, 백엔드에서 데이터만 뽑아와서 시각적으로 뿌려줌(Rendering).
3. **게시판 선행 생성 필수**: 현재 커뮤니티 서브메뉴의 게시판들이 백엔드에서 생성되어 있지 않으므로, 백엔드 게시판 구축 및 API 스키마 확정이 선행되어야 한다.

## 2. 인천하이병원 2WAY (Headless) 아키텍처 흐름

프론트엔드와 백엔드가 완전히 분리되어 각자의 역할에 100% 집중하는 현대적인 분리형 아키텍처입니다.

```text
┌──────────────────────────────────────────────────────────────────────────────────┐
│                   인천하이병원 2WAY (Headless) 아키텍처 흐름                     │
├──────────────────────────────────────────────────────────────────────────────────┤
│                                                                                  │
│  [ 1. 백엔드 시스템 (g7 Core / Laravel / 최우진 대리) ]                          │
│    ├── DB 스키마 자동 생성 (게시판 테이블: news, press, story, consult, faq 등) │
│    ├── 권한 및 보안 제어 (회원 전용 vs 비회원 비밀글 글쓰기 허용 여부)            │
│    ├── 환자 개인정보 암호화 (AES-256 연락처 양방향 암호화, Bcrypt 비밀번호 해싱)│
│    └── RESTful API Gateway (JSON 규격: 목록 제공, 글 저장, 상세 조회 엔드포인트) │
│                               ▲                                                  │
│                               │ (HTTP/HTTPS REST API 비동기 JSON 송수신)         │
│                               ▼                                                  │
│  [ 2. 프론트엔드 시스템 (Next.js 14 App Router / 고윤기 대리 x 정재이 과장) ]    │
│    ├── 독립된 전체 페이지(Full Page) 라우팅 체계 구축                             │
│    │     ① 글 목록 페이지 (/community/[board]) : 페이지네이션, 검색, 카테고리 탭 │
│    │     ② 글 상세 페이지 (/community/[board]/[id]) : 본문, 이전/다음글, 목록버튼 │
│    │     ③ 글 작성 페이지 (/community/[board]/write) : 입력 폼, 비밀번호, 첨부파일│
│    ├── 반응형 프리미엄 UI/UX 렌더링 (1400px 규격, 시니어 친화적 고가독성 타이포)  │
│    └── 사용자 인터랙션 처리 (클라이언트 유효성 검사, 로딩 스켈레톤, 에러 핸들링) │
│                                                                                  │
└──────────────────────────────────────────────────────────────────────────────────┘
```

## 3. 왜 전체 페이지(Full Page) 형태여야 하는가?

게시판 콘텐츠를 팝업 모달이 아닌 독립된 풀 페이지로 구축해야 하는 4대 기술적·경영적 필연성입니다.

```text
┌─────────────────────────────────────────────────────────────────────────┐
│              풀 페이지(Full Page) 게시판이 보장하는 4대 가치             │
├─────────────────────────────────────────────────────────────────────────┤
│  1. 영구 고유 주소 (Permanent URL)  │  네이버/구글 검색엔진 100% 색인   │
│  2. 소셜 바이럴 (OpenGraph Card)    │  카카오톡 공유 시 썸네일 자동 노출 │
│  3. 웹 접근성 & 브라우저 히스토리   │  뒤로가기/앞으로가기 완벽 지원     │
│  4. 전문적인 작성 환경 (Form UX)    │  장문 작성 시 입력 데이터 유실 방지│
└─────────────────────────────────────────────────────────────────────────┘
```

### 1) 영구 고유 주소(Permanent URL)와 검색엔진 최적화(SEO)
- 환자가 네이버나 구글에 "인천하이병원 허리디스크 비수술 후기", "계산역 인공관절 수술" 등을 검색했을 때, 검색엔진 로봇은 개별 페이지의 URL을 크롤링하여 검색 결과 최상단에 노출시킵니다.
- 모달 형태는 단일 URL 안에서 자바스크립트로만 열리기 때문에 검색엔진에 노출되지 않지만, **전체 페이지(`/community/story/15`)는 고유한 HTML 주소를 가지므로 포털 검색 유입을 극대화**할 수 있습니다.

### 2) 카카오톡 및 SNS 링크 공유 (바이럴 마케팅)
- 환자나 보호자가 "이 병원 치료 후기 좀 봐봐"라며 카카오톡 단체방이나 밴드, 블로그에 링크를 복사해 붙여넣었을 때,
- 전체 페이지 구조여야만 **해당 게시글의 대표 썸네일 이미지, 제목, 요약문이 담긴 예쁜 미리보기 카드(OpenGraph 메타태그)**가 자동으로 생성되어 신뢰도 높은 클릭을 유도합니다.

### 3) 브라우저 히스토리 및 사용자 경험(UX)
- 모달창이 열린 상태에서 스마트폰이나 브라우저의 **'뒤로 가기' 버튼을 누르면 이전 웹사이트로 튕겨 나가는 치명적인 이탈 현상**이 발생합니다.
- 풀 페이지 구조에서는 '뒤로 가기' 시 직전에 보던 '게시판 목록 페이지'로 자연스럽게 이동하며, 스크롤 위치가 유지되어 환자가 편안하게 다른 게시글을 탐색할 수 있습니다.

### 4) 안정적인 글쓰기 및 상담 폼 환경
- 1:1 온라인 상담이나 후기 작성 시 모달창은 바깥 영역을 실수로 클릭하면 작성 중이던 장문의 글이 날아갈 위험이 있습니다.
- 독립된 전체 페이지(`/community/consultation/write`)는 안전한 폼 격리를 제공하며, 모바일 키보드가 올라오더라도 화면이 깨지지 않는 안정성을 보장합니다.

## 4. 향후 추진해야 할 선행 작업 순서 (강수진 PM 로드맵)

강수진 실장이 총괄 수립한 3단계 순차 빌드업 실행 계획입니다.

```text
┌──────────────────┐      ┌──────────────────┐      ┌──────────────────┐
│  [1단계: 백엔드] │ ──>  │ [2단계: 프론트]  │ ──>  │ [3단계: 2WAY 결합]│
│  5대 게시판 생성 │      │ 3단 풀페이지 구축│      │ 실시간 API 바인딩│
│ (최우진 대리)    │      │ (고윤기x정재이)  │      │ (최우진x고윤기)  │
└──────────────────┘      └──────────────────┘      └──────────────────┘
```

### 📌 [1단계] 백엔드 5대 핵심 게시판 선행 생성 (최우진 대리)
프론트엔드 개발에 앞서 g7 코어에서 데이터베이스 스키마 및 REST API 엔드포인트를 선제 구축합니다.

| 게시판 ID | 게시판 명칭 | 서비스 성격 | 글쓰기 권한 및 보안 규칙 (제7원칙) |
| :--- | :--- | :--- | :--- |
| `news` | 하이병원 소식 | 공식 공지사항 | 관리자 전용 작성 / 전체 공개 읽기 |
| `press` | 언론보도 | 방송 및 신문 보도 | 관리자 전용 작성 / 언론사 링크 지원 |
| `story` | 환자 치료 스토리 | 생생한 완치 인터뷰 | 환자 성명 마스킹(`박OO 환자`), 연령 표기 |
| `consultation` | 1:1 온라인 상담 | 비공개 증상 상담 | **비회원 글쓰기 허용**, **Bcrypt 패스워드**, **AES-256 연락처 암호화** |
| `faq` | 자주 묻는 질문 | 병원 이용 가이드 | 카테고리별 아코디언 조회 |

- **산출물**: 
  - 각 게시판 테이블 마이그레이션 (`php artisan migrate`)
  - 고품질 의료 콘텐츠 시더 데이터 주입 (`php artisan db:seed`)
  - REST API Swagger 명세서 업데이트

### 📌 [2단계] 프론트엔드 3단 전체 페이지(Full Page) 템플릿 구축 (고윤기 대리 & 정재이 과장)
모든 게시판에 일관되게 적용될 수 있는 확장형 공통 게시판 라우팅 및 템플릿 컴포넌트를 개발합니다.

```text
lsk-frontend/src/app/community/
├── layout.tsx                     # 커뮤니티 공통 LNB 사이드바 & 상단 비주얼 배너
├── [board]/
│   ├── page.tsx                   # [1] 글 목록 페이지 (List: 테이블/그리드 카드, 검색, 페이징)
│   ├── write/
│   │   └── page.tsx               # [2] 글 작성/수정 페이지 (Write: 비회원 비밀번호, 입력 폼)
│   └── [id]/
│       └── page.tsx               # [3] 글 상세 페이지 (View: 본문, 이전/다음글, 첨부파일)
```

1. **[1] 글 목록 페이지 (`page.tsx`)**:
   - 상단 카테고리 탭 버튼 (의료진/시설 필터에서 검증된 스크롤바 없는 안정 탭)
   - 일반 공지형(테이블 뷰)과 치료 스토리형(카드 썸네일 뷰)을 지원하는 동적 뷰 스위처
   - 10개 단위 페이지네이션 및 검색창(`keyword`)
2. **[2] 글 상세 페이지 (`[id]/page.tsx`)**:
   - 제목, 작성일, 조회수, 담당 진료과 뱃지
   - 본문 렌더러 (위지윅 에디터 HTML 지원 및 폰트 가독성 최적화)
   - 하단 '이전글 / 다음글' 네비게이션 및 '목록으로 돌아가기' 버튼
   - 비공개 상담글인 경우 비밀번호 확인 폼 자동 렌더링
3. **[3] 글 작성 페이지 (`write/page.tsx`)**:
   - 비회원 상담 작성자를 위한 성명, 연락처, 비밀번호 입력 필드
   - 개인정보 수집 및 이용 동의 체크박스 필수 연동
   - 정재이 과장의 직관적인 에러 피드백 UI

---

### 📌 [3단계] 2WAY 실시간 데이터 바인딩 및 보안 암호화 연동 (최우진 대리 x 고윤기 대리)
1. **비동기 데이터 페칭**:
   - 프론트엔드 목록 페이지에서 `GET /api/v1/boards/{board}/posts?page=1` 호출 후 화면 렌더링.
2. **폼 데이터 전송 및 암호화**:
   - 환자가 1:1 상담글 작성 후 등록 클릭 시 `POST /api/v1/boards/consultation/posts`로 안전 전송.
   - 백엔드는 환자의 연락처를 `AES-256-GCM`으로 암호화하여 DB 저장.
3. **완전한 통합 테스트**:
   - 환자 글 작성 → 관리자 답변 등록 → 환자 비밀번호 인증 후 비밀글 열람의 전체 라이프사이클 검증.

## 5. 결론 및 향후 회의 보고 사항

대표님께서 짚어주신 **"게시판은 전체 페이지 형태여야 하며, 백엔드 선행 생성 후 프론트에서 데이터를 뽑아 뿌려주는 2WAY 방식"**은 향후 인천하이병원 디지털 플랫폼이 대규모 환자 유입과 안정적인 원무 행정을 뒷받침할 수 있는 가장 튼튼한 반석입니다.

팀원 전원은 본 로드맵을 지침 삼아, 다음 작업 착수 시 **[최우진 대리의 백엔드 게시판 DB 구축] → [고윤기 대리의 커뮤니티 3단 풀페이지 구축]** 순으로 일사불란하게 진행할 것을 약속드립니다.
