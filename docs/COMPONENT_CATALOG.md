## 1. 초보자를 위한 핵심 개념 정리

개발 현장에서 자주 쓰이는 단어들이 헷갈리실 때, **"자동차 조립"** 또는 **"병원 건물 짓기"**로 비유하면 아주 쉽습니다.

```
┌────────────────────────────────────────────────────────────────────────┐
│ [개념 구조도]                                                          │
│                                                                        │
│   모듈 (Module) : 하나의 완결된 기능 묶음 (예: "엔진 시스템", "내비 파일") │
│     │                                                                  │
│     ├── 클래스 (Class) : 설계도 붕어빵 틀 (데이터와 동작을 묶은 구조)   │
│     ├── 컴포넌트 (Component) : 눈에 보이는 완성된 레고 블록 (버튼, 헤더) │
│     └── 함수 (Function) : 특정 동작 하나만 하는 일꾼 (계산기, 포맷터)  │
└────────────────────────────────────────────────────────────────────────┘
```

| 용어 | 쉬운 일상 비유 | 프론트엔드 웹 개발에서의 실제 의미 | 우리 프로젝트의 실제 예시 |
| :--- | :--- | :--- | :--- |
| **컴포넌트 (Component)** | **눈에 보이는 '레고 블록'** | HTML(뼈대) + CSS(모양) + JS(동작)가 합쳐져서 화면에 한 덩어리로 나타나는 UI 부품 | `Gem_Header.tsx`<br>`Gem_QuickMenu.tsx`<br>`Gem_HeroCarousel.tsx` |
| **모듈 (Module)** | **부품들을 담아둔 '공구함' 또는 '부품 세트'** | 독립된 기능을 수행하기 위해 관련된 코드(컴포넌트, 함수, 설정 등)를 파일 하나로 깔끔하게 묶어둔 단위 | `navigationData.ts` (메뉴 데이터 모듈)<br>`api/reservation.ts` (예약 전송 모듈) |
| **클래스 (Class)** | **동일한 규격의 부품을 찍어내는 '설계도(붕어빵 틀)'** | 객체 지향 프로그래밍에서 데이터(속성)와 기능(메서드)을 정의해 둔 틀. *최신 React/Next.js는 클래스 대신 가벼운 함수형 컴포넌트를 표준으로 사용합니다.* | 백엔드 그누보드7/FastAPI의 `UserModel`, 스타일링을 위한 CSS 클래스명 (`class="btn"`) |
| **함수 (Function)** | **특정 심부름을 해주는 '일꾼'** | 어떤 값을 입력받으면 정해진 규칙대로 계산하거나 변환해서 결과를 돌려주는 코드 조각 | `formatPhoneNumber('01012345678')`<br>`encryptPatientData(data)` |

> **💡 요약 정리**: 
> 대표님께서 화면에서 눈으로 보시고 *"이 부분 수정해 주세요"* 하시는 단위는 99% **「컴포넌트(Component)」**입니다. 앞으로는 이 명세서의 컴포넌트 이름으로 말씀해 주시면 개발진이 즉각 정확하게 대응할 수 있습니다.

## 2. 공통 아키텍처 및 코딩 표준 규격

### 2.1. 레이아웃 및 컨테이너 규격
- **최대 기준 너비 (Max Width)**: `max-w-[1400px]` (중앙 정렬 `mx-auto`)
- **패딩 가이드**:
  - 데스크톱 (Desktop $\ge$ 1280px): 좌우 `px-8` (32px)
  - 태블릿 (Tablet 768px ~ 1279px): 좌우 `px-6` (24px)
  - 모바일 (Mobile $\le$ 767px): 좌우 `px-4` (16px)

### 2.2. 접두사 규칙 (`Gem_`) 및 네임스페이스 격리
- **명명 규칙**: 모든 공통 UI 컴포넌트는 `Gem_` 접두사를 의무적으로 사용합니다. (예: `Gem_Header.tsx`)
- **네임스페이스 격리**: 향후 그누보드의 레거시 플러그인, jQuery 또는 외부 서드파티 스크립트와의 전역 변수/함수 이름 충돌을 100% 차단하기 위해 모든 DOM 식별자와 CSS 루트 클래스에 `gem-` 네임스페이스를 부여합니다.

### 2.3. 렌더링 전략 분리 기준 (SSG vs CSR)
- **SSG (Static Site Generation, 정적 렌더링)**:
  - **적용 대상**: 검색엔진(SEO) 노출이 중요하고 내용이 자주 바뀌지 않는 콘텐츠 (병원 소개, 진료과목 안내, 시설 갤러리 뼈대 등)
  - **장점**: 첫 페이지 로딩 속도 극대화, 서버 부하 제로.
- **CSR (Client-Side Rendering, 동적 렌더링)**:
  - **적용 대상**: 사용자 인터랙션이 발생하거나 실시간 데이터 조회가 필요한 컴포넌트 (온라인 간편예약 폼, 실시간 최신 환자후기, 3D 모델 인터랙션, 드롭다운 메뉴 상태)
  - **표기**: 파일 최상단에 `'use client';` 지시어 필수 부착.

## 3. 제1그룹: 글로벌 네비게이션 및 UI 컨트롤 모듈 (Global UI)

### 3.1. 상단 네비게이션 및 메가메뉴 통합 모듈 (`Gem_Header.tsx`)
- **파일 경로**: `lsk-frontend/src/components/Gem_Header.tsx`
- **배치 위치**: 전 페이지 공통 최상단 (Sticky 고정)
- **화면 역할**:
  1. 병원 대표 로고 표시 (클릭 시 메인 홈 `/` 이동)
  2. 1depth 메인 메뉴 호버 시 2depth 서브메뉴가 펼쳐지는 드롭다운
  3. 햄버거 버튼 클릭 시 전체 메뉴를 한눈에 볼 수 있는 메가 메뉴(Mega Menu) 풀스크린 모달 호출
  4. 빠른 전화상담 버튼(`032-219-0100`) 및 진료예약 바로가기
- **렌더링 방식**: **CSR (`'use client'`)** - 스크롤 감지 시 배경 투명도 전환, 드롭다운/메가메뉴 상태 관리.
- **데이터 구조**: `src/data/navigationData.ts` 모듈로부터 네비게이션 트리 데이터를 import하여 주입.
- **스타일링**: Tailwind CSS (`sticky top-0 z-50 backdrop-blur-md border-b`)
- **수정 포인트 (대표님 확인용)**:
  - 메뉴 명칭 또는 메뉴 링크를 바꾸고 싶을 때 $\rightarrow$ `src/data/navigationData.ts` 수정
  - 헤더 높이, 로고 크기, 전화번호 문구를 바꾸고 싶을 때 $\rightarrow$ `Gem_Header.tsx` 수정

### 3.2. 우측 플로팅 퀵메뉴 모듈 (`Gem_QuickMenu.tsx`)
- **파일 경로**: `lsk-frontend/src/components/Gem_QuickMenu.tsx`
- **배치 위치**: 화면 우측 하단 고정 (스크롤을 따라다니는 Floating UI)
- **화면 역할**:
  1. 카카오톡 상담 바로가기 링크 (외부 채널 연동)
  2. 간편 전화상담 연결 (`tel:` 프로토콜)
  3. 빠른 온라인 예약 앵커 이동
  4. 최상단으로 부드럽게 스크롤 이동하는 Top 버튼
- **렌더링 방식**: **CSR (`'use client'`)** - 스크롤 위치에 따라 Top 버튼 노출 여부 토글, 클릭 이벤트 처리.
- **반응형 전략**: 모바일 화면에서는 하단 바(Bottom Bar) 형태로 압축되거나 아이콘 형태로 자동 전환.
- **수정 포인트**: 카카오톡 상담 채널 URL, 대표 전화번호 연결 변경.

### 3.3. 전 페이지 공통 푸터 모듈 (`Gem_Footer.tsx`)
- **파일 경로**: `lsk-frontend/src/components/Gem_Footer.tsx`
- **배치 위치**: 전 페이지 최하단
- **화면 역할**:
  1. 병원 사업자등록번호, 대표자명, 의료기관 등록정보, 병원 주소 표기
  2. 평일/토요일/공휴일/응급실 진료시간 상세 안내
  3. 개인정보처리방침, 환자의 권리와 의무, 비급여 진료비 안내 등 법정 고지 링크
  4. 찾아오시는 길(오시는 길 안내 및 주차 안내)
- **렌더링 방식**: **SSG (정적 렌더링)** - 검색엔진 크롤러가 병원 메타정보를 신속히 수집하도록 정적 HTML로 생성.
- **수정 포인트**: 진료시간 변경, 대표자/사업자번호 텍스트 갱신, 저작권 문구 수정.

## 4. 제2그룹: 히어로 및 인터랙션 모듈 (Hero & Interaction)

### 4.1. 히어로 메인 비주얼 배너 (`Gem_HeroCarousel.tsx`)
- **파일 경로**: `lsk-frontend/src/components/Gem_HeroCarousel.tsx`
- **배치 위치**: 메인 인덱스 최상단 헤더 바로 밑 (첫 인상을 좌우하는 메인 영역)
- **화면 역할**:
  1. 병원의 핵심 슬로건("척추·관절 비수술 중심 치료", "대학병원급 첨단 검사장비") 롤링
  2. 7초 간격 자동 슬라이드, 마우스 호버(Hover) 시 타이머 일시정지(Pause)
  3. 양옆 이전/다음 넘김 화살표 및 하단 인디케이터 바(게이지 바)
  4. 차세대 WebP/AVIF 고화질 이미지 및 3D 그래픽 에셋 서빙 (LCP 우선순위 `priority={true}`)
- **렌더링 방식**: **CSR (`'use client'`)** - 타이머 기반 슬라이드 애니메이션, 드래그/터치 스와이프 제어.
- **스타일링**: Framer Motion / CSS 키프레임 기반 부드러운 페이드인-아웃 트랜지션.
- **수정 포인트**: 슬라이드 배너 이미지 변경, 홍보 카피 문구 수정, 슬라이드 전환 속도 조정.

### 4.2. 신체 부위별 질환 인터랙티브 맵 (`Gem_InteractiveBody3D.tsx`)
- **파일 경로**: `lsk-frontend/src/components/Gem_InteractiveBody3D.tsx`
- **배치 위치**: 메인 인덱스 히어로 하단 또는 특화센터 상단
- **화면 역할**:
  1. 신체 모형도(목, 허리, 어깨, 무릎, 손/발목 등) 시각화
  2. 환자가 아픈 부위를 클릭하거나 탭을 선택하면, 해당 부위의 대표 질환(예: 목디스크, 척추관협착증, 퇴행성관절염)과 맞춤 비수술 치료법이 실시간으로 동적 전환
  3. 해당 진료센터 및 질환 상세 서브페이지(`/centers/spine`, `/diseases/cervical-disc`)로 연결
- **렌더링 방식**: **CSR (`'use client'`)** - 부위 선택 활성 상태(`selectedPart`)에 따른 탭 컨텐츠 실시간 스위칭.
- **충돌 방지**: Three.js 또는 SVG 기반 바닐라 JS 요소를 독자적인 컨테이너 Ref(`useRef`) 내에 캡슐화하여 전역 스코프 오염 차단.
- **수정 포인트**: 부위별 질환 리스트 추가, 설명 문구 변경, 바로가기 서브페이지 링크 매핑.

## 5. 제3그룹: 폼 및 데이터 입력 모듈 (Forms & Inputs)

### 5.1. 원스톱 간편예약 신청 바 (`Gem_QuickReservationBar.tsx`)
- **파일 경로**: `lsk-frontend/src/components/Gem_QuickReservationBar.tsx`
- **배치 위치**: 메인 인덱스 히어로 배너 하단 가로 바(Bar) 형태 또는 플로팅 연동
- **화면 역할**:
  1. 복잡한 로그인 없이 성함, 연락처, 희망 진료과목(척추센터, 관절센터, 내과 등), 희망 일시 선택
  2. 개인정보 수집 및 이용 동의 체크박스 및 모달 약관 안내
  3. 전화번호 정규식 유효성 검사 (010-XXXX-XXXX 자동 포맷팅)
  4. 원클릭 접수 완료 시 안심 확인 토스트(Toast) 알림
- **렌더링 방식**: **CSR (`'use client'`)** - 폼 상태 관리(`useState`), 사용자 입력값 유효성 검증.
- **그누보드7 백엔드 연동 방안**:
  - `POST /api/v1/reservations/quick` 엔드포인트로 비동기(`fetch`/`axios`) 전송.
  - **보안/암호화 의무 준수**: 환자의 이름과 연락처는 전송 시 전송 구간 HTTPS(TLS 1.3) 및 백엔드 저장 시 AES-256 단방향/양방향 암호화 필드 처리.
- **수정 포인트**: 진료과목 드롭다운 항목 추가, 개인정보 안내 약관 문구 수정.

## 6. 제4그룹: 데이터 전시 및 실적 통계 모듈 (Data Display)

### 6.1. 임상 실적 및 수술 건수 통계 카운트업 (`Gem_ClinicalMetrics.tsx`)
- **파일 경로**: `lsk-frontend/src/components/Gem_ClinicalMetrics.tsx`
- **배치 위치**: 메인 인덱스 중단 (병원 신뢰도 증명 섹션)
- **화면 역할**:
  1. 척추·관절 누적 수술/치료 건수 (예: 50,000건+), 환자 치료 만족도 (98.4%), 무사고 기간 등 주요 지표 카드
  2. 사용자가 화면을 스크롤하여 해당 섹션에 도달할 때 숫자가 `0`부터 목표치까지 스르륵 차오르는 카운트업(CountUp) 애니메이션 작동
- **렌더링 방식**: **CSR (`'use client'`)** - `IntersectionObserver` 스크롤 감지 및 카운트업 타이머 실행.
- **수정 포인트**: 대표 실적 숫자(수술 건수, 만족도 비율), 타이틀 라벨 문구 수정.

  3. 클릭 시 각 센터별 원스크롤 상세 안내 페이지(`Gem_SpineCenterOneScrollPage`)로 이동
- **렌더링 방식**: **SSG (기본 카드 뼈대 및 SEO 텍스트) + 미세 호버 인터랙션**
