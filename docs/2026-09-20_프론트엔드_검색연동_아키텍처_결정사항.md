# 프론트엔드(Next.js) - 그누보드7 검색 연동 아키텍처 결정 사항

**작성일자:** 2026년 09월 20일
**작성자:** 김별 (기록 담당)
**관련 프로젝트:** 인천하이병원 리뉴얼 (Next.js + GnuBoard 7 Headless)

---

## 1. 개요 및 목적
현재 프론트엔드(Next.js)로 구축 중인 화려하고 동적인 서브 페이지(예: 척추측만증 등 3D 컴포넌트 포함 페이지)들을 그누보드7의 **'통합 검색' 결과에 정상적으로 노출**시키기 위한 아키텍처 방향성을 확정합니다.

## 2. 결정된 아키텍처: [2안] 검색용 더미 페이지 + 리다이렉트 방식
전통적인 서버 사이드 렌더링(SSR)이나 복잡한 API 연동 방식 대신, **Next.js의 디자인 자유도를 100% 보장하면서 그누보드의 검색 엔진을 활용하는 하이브리드(꼼수) 방식**을 채택합니다.

### 2.1. 작업 흐름 (Workflow)
1. **프론트엔드 구축 (Next.js):** 
   - 프론트엔드 개발자/디자이너는 그누보드 구조에 얽매이지 않고, 텍스트와 UI가 모두 포함된 완성형 정적/동적 페이지를 구현합니다.
2. **그누보드 더미 페이지 생성 (백엔드):** 
   - 그누보드7 관리자 모드 > [페이지 관리]에서 프론트엔드 페이지와 매칭되는 '더미(Dummy) 페이지'를 생성합니다.
   - 이때 디자인 요소(HTML/CSS)는 배제하고, 검색에 걸려야 할 **'순수 텍스트(키워드, 본문 내용)'**만 복사하여 붙여넣습니다.
3. **검색 리다이렉트 (Search Redirect):**
   - 사용자가 그누보드 통합 검색을 통해 질환명 등을 검색하면, 그누보드는 DB에 저장된 더미 페이지 텍스트를 찾아내어 검색 결과에 노출합니다.
   - 검색 결과 목록에서 해당 페이지 링크를 클릭할 경우, 그누보드의 원본 더미 페이지 화면이 뜨는 것이 아니라 **Next.js 프론트엔드의 실제 페이지 URL로 즉시 이동(Redirect)** 되도록 자바스크립트 또는 백엔드 라우팅 처리를 추가합니다.

## 3. 기대 효과 및 장점
- **디자인 제약 제로:** 그누보드 에디터의 한계(React 컴포넌트 불가 등)를 완벽히 우회하여 최신 웹 기술(3D, 스크롤 애니메이션 등)을 제약 없이 사용 가능.
- **빠른 개발 속도:** 복잡한 Headless CMS API 구축 및 프론트엔드 상태 관리를 생략하고, 직관적인 페이지 매칭만으로 검색 기능 구현 완료.
- **유지보수 용이:** 검색 노출용 키워드를 수정하고 싶을 때, 개발자 개입 없이 관리자가 그누보드 어드민에서 텍스트만 덧붙이면 됨.
